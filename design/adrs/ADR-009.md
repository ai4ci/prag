## Context
A retrieval system needs clear boundaries for what is indexed. Users expect two seemingly conflicting behaviors:
1. **Container discovery:** Pointing `prag watch file://~/Git` should watch that directory and discover/index all repositories inside without manual setup for each one.
2. **Exclusion and removal:** Running `prag deny file://~/Git/my-secret-project` should remove that directory from search and ensure subsequent file modifications never re-trigger indexing or Chokidar watching.

Relying on filesystem markers (like `.prag` or `.prag.yaml`) creates dirty working trees, requires `.gitignore` edits, breaks on read-only checkouts, and fails completely for remote web URIs. Furthermore, treating container roots like `~/Git` as a single project breaks Git branch awareness across child repositories.

## Decision
1. **Unified URI Grants Policy (`grants` table):**
   - All access and indexing permissions are governed by an allow/deny rule set over normalized URIs stored in LanceDB (`pattern`, `action: allow | deny`, `reason`, `createdAt`).
   - Evaluation semantics follow standard longest-prefix matching (most specific rule wins; `deny` breaks ties).
   - Before Chokidar monitors a directory, or before a discovery scan descends, candidate URIs are evaluated against `grants`.
2. **Decoupling Grants from Projects:**
   - **`grants`** governs *policy* (what URI space is permitted to be monitored or indexed).
   - **`projects`** governs *versioning & scoping* (what discrete Git repositories, non-git folders, or web namespaces exist within the allowed URI space).
3. **Atomic Projects within Allowed URI Space:**
   - When the scanner traverses allowed URI space and encounters a `.git/` folder, it registers that boundary as an autonomous Project (`isGit: true`).
   - Non-git folders and web namespaces form projects operating under the `$default` branch sentinel.
4. **Deny & Removal Semantics:**
   - Running `prag deny <uri>` inserts a `deny` rule with `<normalized_uri>/**`.
   - Any project data or chunks rooted under that URI are immediately purged from `projects` and `branch_mapping`.
   - The live Chokidar watcher immediately un-watches the subtree because `evalGrant(uri)` evaluates to `deny`.

## Evaluated Alternatives Ruled Out
- **Filesystem Marker Files (`.prag`, `.prag.yaml`):**
  - *Why considered:* Decentralized, lives alongside the project.
  - *Why ruled out:* Pollutes user repositories, requires gitignore changes, impossible on remote web URIs or read-only directories.
- **Treating Container Directories as a Single Giant Project:**
  - *Why considered:* Avoids multi-project breakdown.
  - *Why ruled out:* Child repositories have different active branches and lifecycles, causing branch collisions and requiring complex path-exclusion trees.
- **Separate Watch Roots and Exclusions Tables:**
  - *Why considered:* Split allow and deny into separate tables.
  - *Why ruled out:* Creates ambiguity when paths overlap; a unified allow/deny rule set with longest-prefix matching provides deterministic, standard security semantics.

## Consequences
- Clean separation between policy (`grants`) and versioning context (`projects`).
- Works uniformly across local filesystem URIs (`file:///...`) and remote web URIs (`https://...`).
- `prag deny` reliably silences filesystem watching and prevents re-indexing.
