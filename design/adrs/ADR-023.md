## Context
`prag watch ~/Git` is a documented example in `cli-and-mcp-interface.md`: a container directory that discovers every child repository beneath it. Nothing in the design caps what that produces. There is no maximum file size, no behaviour defined at 100,000 files, and no way to stop a scan short of deleting the grant. A 2GB log file, a 50MB minified bundle, or two hundred repositories are all currently in scope by default.

One property makes this much cheaper to solve than it first appears: **the ingestion queue holds URIs, not file content.** Half a million paths is tens of megabytes of memory. The constraint is therefore throughput and CPU, not queue memory — so a bounded queue with disk spillover would be solving a problem that does not exist. The effort belongs in not enqueuing the work at all.

## Decision
1. **Filter at discovery, not at ingestion.** Two checks run when the scanner or Chokidar first sees a path, before anything is enqueued:
   - `ingestion.maxFileBytes` (default `2097152`, 2MB) — larger files are skipped.
   - Binary detection — a NUL byte in the first 8KB marks the file binary and it is skipped. This is in addition to, not instead of, the built-in ignore grants (ADR-009), which already exclude `node_modules`, `.git`, `dist` and friends.
   Skipped files are never read twice and never enter the queue.
2. **Always report what was skipped.** Per-project counters, broken down by reason (`tooLarge`, `binary`, `denied`), are returned by `GET /projects` and rendered by `prag status` — e.g. `1,203 skipped (40 too large, 1,163 binary)`. A limit the user cannot see is indistinguishable from the tool silently failing to index their code, which is the fastest way to lose their trust in search results. Counters are per-scan and held in memory; they are rebuilt by the next scan and deliberately not persisted to the schema.
3. **Admission control on `prag watch`.** When a grant would register more than `ingestion.watchConfirmThreshold` projects or files (default: 25 projects or 20,000 files), the CLI performs a discovery dry run, prints what *would* be indexed, and requires `--yes` to proceed. This is the highest-value guard in this ADR: it stops the `~/Git` foot-gun at the moment the grant is created, rather than six hours into the CPU burn. The MCP `watch_uri` tool applies the same threshold and fails with a `code` identifying the limit (ADR-022) rather than prompting, since an agent has no terminal to confirm at.
4. **Fixed concurrency cap.** Ingestion runs at a bounded rate tied to the existing `embedding.batchSize` and `ingestion.workerPoolSize` (ADR-021), so indexing never saturates the machine regardless of how much work is outstanding.
5. **`prag pause <project>` / `prag resume <project>`.** `projects.status = 'paused'` already exists in the schema but nothing sets it. Exposing it gives a runaway scan an off switch that does not require deleting the grant and discarding the work already done.
6. **No backpressure mechanism for the dirty set.** It is a set keyed by URI, so repeated edits to the same file collapse into one entry by construction (ADR-008). Nothing further is needed.

## Evaluated Alternatives Ruled Out
- **Bounded queue with disk-backed overflow:** standard advice, and wrong here. The queue holds paths, so it is already bounded in any realistic case; this would add a persistence layer to solve a problem that does not occur.
- **Silently skipping oversized and binary files:** cheapest, and the default most tools land on. Rejected — a user whose file is missing from search results has no way to distinguish a deliberate limit from a bug, so the counters in point 2 are not optional polish.
- **Indexing large files in truncated form:** keeps them findable, but a truncated 2GB log is noise in the index and the vectorised-unit machinery (ADR-014) would faithfully embed all of it. Skipping is the honest behaviour.
- **A hard cap on total indexed files per project:** blunt, and fails in the wrong direction — it silently stops partway through a legitimate large repository. Admission control at grant time addresses the same risk while leaving the user in charge.

## Consequences
- The documented `prag watch ~/Git` example becomes safe: it asks before committing the machine to hours of work.
- Oversized and binary files are visibly excluded rather than quietly missing.
- Three new config keys (`ingestion.maxFileBytes`, `ingestion.watchConfirmThreshold`, `ingestion.workerPoolSize` from ADR-021) and two new CLI commands (`pause`, `resume`).
- `project-registry-and-status.md`, `background-worker-queue.md` and `cli-and-mcp-interface.md` are updated.
