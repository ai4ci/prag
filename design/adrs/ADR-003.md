## Context
Unified multi-language support (including data science layouts like R) requires robust AST tree mapping, while document layout mapping requires layout awareness.

## Decision
Standardize on Tree-sitter (via automated multi-language wrapper registries: `tree-sitter-language-pack`) for programming files and LiteParse for localized binary layouts (PDF/Word). Tree-sitter is used for content-dependent chunking, code chunk whitespace normalisation, and code chunk context management. LiteParse converts rich text directly into cleanly structured local Markdown strings.

## Consequences
Avoids manual tree-walking logic across different languages by outsourcing grammar node configurations to an auto-downloading engine runtime.

## Evaluated Alternatives Ruled Out
### Fixed-Token / Naive Character Chunking (LangChain Standard Splitters)
- **What it is:** Slicing code files strictly by arbitrary token counts or character length rules (e.g. every 512 tokens).
- **Why considered:** Standard fallback method for general-purpose text processing pipelines.
- **Why ruled out:** Completely breaks source code semantics. Blindly slicing code fragments mid-sentence splits variables from execution context or cuts logical scopes (loops, functions) in half, corrupting vector embedding accuracy.
- **The prag Shift:** Replaced by Tree-sitter node boundary parsing, operating as a 'smart ruler' to extract structurally whole, logically independent functional grammar blocks.

### Raw AST Token Vectorization
- **What it is:** Passing raw Abstract Syntax Tree (AST) structural token arrays directly to an embedding layer instead of text code blocks.
- **Why considered:** Attempt to capture purely mathematical syntax trees without relying on text naming variations.
- **Why ruled out:** Standard pre-trained transformer embedding models do not know how to interpret raw abstract token graphs. Pre-trained polyglot code models are trained on human-readable GitHub source code text, relying on contextual patterns, formatting conventions, and descriptive names.
- **The prag Shift:** Tree-sitter is strictly confined to identifying chunking borders. The extracted raw code string is what gets passed to the tokenizer of the local embedding model.

### General-Purpose Agent Orchestration (LangChain)
- **What it is:** Framework for composing LLM chains and tools.
- **Why considered:** Default marketing recommendation for constructing RAG pipelines.
- **Why ruled out:** Engineered for high-level agent orchestration and tool use, but features weak layout parsing defaults. Passing binary layout documents like PDFs or Word files results in naive string extraction that mangles multi-column structures, embedded tables, and footnotes.
- **The prag Shift:** Replaced by LlamaIndex (@llamaindex/liteparse), engineered explicitly for structure-aware parsing, section hierarchy mapping, and native Apache Arrow vector store bindings.
