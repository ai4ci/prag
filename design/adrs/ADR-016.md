## Context
Lazy-spawn relies on `GET /health` responding before the CLI trusts a port. Two distinct failure modes exist: (a) the port is held by a completely unrelated process that happens to answer HTTP, and (b) the port is held by a genuine `prag` daemon speaking an incompatible protocol (e.g. after upgrading `@prag/cli` without restarting `@prag/daemon`).

Comparing package versions is the wrong test for (b). `@prag/cli` and `@prag/daemon` are separately versioned packages in one monorepo, so a CLI-only patch release — a terminal formatting fix, say — would hard-fail against a perfectly compatible daemon.

## Decision
1. `GET /health` returns `service: "prag-daemon"`, `apiVersion` (an integer, bumped **only** when the HTTP/JSON or MCP tool contract changes incompatibly), and `version` (the daemon's package semver, for diagnostics and bug reports only), in addition to the existing `{ status, pid, uptime, port }`.
2. On lazy-spawn or any ordinary command, the CLI inspects the response:
   - If `service` is missing or not `"prag-daemon"`, it fails loudly — **no automatic port fallback or scanning** — with a message instructing the user to set a different port explicitly (`PRAG_PORT=<n>` or `server.port` in `config.json`) or stop the conflicting process.
   - If `service` matches but `apiVersion` differs from the CLI's own, it also fails loudly rather than talking to a protocol-skewed daemon, instructing the user to run `prag daemon stop` so the next invocation respawns at the current version.
   - `version` is **never** compared. It is reported in error output only.
3. **Lifecycle commands are exempt from the `apiVersion` check:** `prag daemon stop`, `status`, `token` and `rotate-secret` proceed against any process identifying as `prag-daemon`. Without this exemption the documented remedy for a version mismatch (`prag daemon stop`) would fail with the very error it is meant to clear, leaving the user to find and kill the PID by hand. These commands still require a matching `service` marker, and `stop`/`token`/`rotate-secret` still require the bearer token (ADR-013).
4. No fallback port-scanning is implemented. The daemon's address stays deterministic and configuration-driven rather than auto-discovered, so MCP host configs (which hardcode the URL) never go stale silently.

## Evaluated Alternatives Ruled Out
- **Comparing package semver instead of `apiVersion`:** rejected — forces a daemon restart on every unrelated patch release of either package, training users to ignore the error.
- **Automatic fallback to the next free port in a range:** rejected — a silently different port on every run breaks hardcoded MCP host URLs and trades one confusing failure for another.
- **Stale-PID/advisory-lock handling (`flock` on a `daemon.lock` file):** a related but separate failure mode (crashed daemon, PID reused by an unrelated process); not addressed by this ADR and left as potential future hardening if it proves to matter in practice.

## Consequences
- A genuine port conflict or protocol skew is surfaced immediately and specifically instead of silently talking to the wrong process or a stale daemon.
- Routine patch upgrades of either package do not disturb a running daemon; only a deliberate `apiVersion` bump does.
- The recovery path out of a mismatch always works, because the commands that perform recovery do not enforce the check that triggered it.
- `background-worker-queue.md`'s `/health` contract and `cli-and-mcp-interface.md`'s lazy-startup section are updated.
