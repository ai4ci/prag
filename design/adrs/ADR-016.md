## Context
Lazy-spawn relies on `GET /health` responding before the CLI trusts a port. Two distinct failure modes exist: (a) the port is held by a completely unrelated process that happens to answer HTTP, and (b) the port is held by a genuine `prag` daemon running an incompatible version (e.g. after upgrading `@prag/cli` without restarting `@prag/daemon`).

## Decision
1. `GET /health` gains `service: "prag-daemon"` and the daemon's own semver `version`, in addition to the existing `{ status, pid, uptime, port }`.
2. On lazy-spawn or `prag daemon status`, the CLI inspects the response:
   - If `service` is missing or not `"prag-daemon"`, it fails loudly — **no automatic port fallback or scanning** — with a message instructing the user to set a different port explicitly (`PRAG_PORT=<n>` or `server.port` in `config.json`) or stop the conflicting process.
   - If `service` matches but `version` differs from the CLI's own version, it also fails loudly rather than attempting to talk to a version-skewed daemon, instructing the user to run `prag daemon stop` (so the next invocation respawns at the current version) or align versions manually.
3. No fallback port-scanning is implemented. The daemon's address stays deterministic and configuration-driven rather than auto-discovered, so MCP host configs (which hardcode the URL) never go stale silently.

## Evaluated Alternatives Ruled Out
- **Automatic fallback to the next free port in a range:** rejected — a silently different port on every run breaks hardcoded MCP host URLs and trades one confusing failure for another.
- **Stale-PID/advisory-lock handling (`flock` on a `daemon.lock` file):** a related but separate failure mode (crashed daemon, PID reused by an unrelated process); not addressed by this ADR and left as potential future hardening if it proves to matter in practice.

## Consequences
- A genuine port conflict or version skew is surfaced immediately and specifically instead of silently talking to the wrong process or a stale daemon.
- Upgrading `@prag/cli` without restarting `@prag/daemon` is now a hard, actionable stop rather than a confusing runtime error from a mismatched API shape.
- `background-worker-queue.md`'s `/health` contract and `cli-and-mcp-interface.md`'s lazy-startup section are updated.
