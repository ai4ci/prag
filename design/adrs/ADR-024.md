## Context
ADR-012 resolved the contradiction between "100% air-gapped" language and web
ingestion by scoping the guarantee to *default behaviour* and mandating that the
web-fetch backend be self-hostable. Two problems with that resolution have since
become clear.

1. **It was scoped around the wrong thing.** No runtime that indexes web content
   is air-gapped, and pretending otherwise produced documentation that hedged its
   own claims. The guarantee users actually rely on is narrower and much stronger:
   content that lives on their machine is parsed, chunked, hashed, embedded and
   stored **on their machine**. That half of the system genuinely can run with no
   network at all. Web fetching is a separate, explicitly granted path, and a
   hosted vendor is an acceptable implementation of it.

2. **It named one vendor and one capability shape.** ADR-012 assumed Firecrawl
   (self-hosted or hosted) plus a "lightweight headless fetcher" fallback. Real
   candidate backends do not share a capability set. Firecrawl fetches a page live
   and can crawl a site. Exa is a search *index*: its Contents endpoint returns
   Markdown taken from a copy of unknown age, mitigated by a cache-age parameter
   rather than by an unconditional live fetch, and it has no site-crawl notion at
   all. A plain HTTP fetcher can retrieve one URL and nothing else. A single
   `fetch(url)` interface would either have to be the intersection of these
   (no crawling, no discovery) or leak vendor-specific options.

## Decision
**1. The local-first guarantee replaces the air-gap guarantee.** It applies to
local content and is unconditional:

- For `file://` projects, parsing, chunking, whitespace normalization, hashing,
  embedding and storage all execute on the local machine. No indexed local
  content, and no query derived from it, is sent anywhere.
- An index-and-search cycle over local content completes with **no network
  reachable at all** — not "no network configured", but genuinely unreachable.
  This is the assertion the CI check makes.
- Telemetry, analytics and usage reporting remain prohibited unconditionally,
  regardless of any configuration.
- Embedding remains local (ADR-006). Configuring a hosted fetch backend never
  makes a hosted inference endpoint legal; those are independent axes.

**2. Web fetching is not covered by that guarantee and may be hosted.** A backend
may be a third-party service. It is used only for URIs the user explicitly
granted, it is always visible in `prag status` / `GET /health` (backend id and
endpoint) so the current egress path is inspectable, and credentials for it are
supplied by the user's own configuration.

**3. The fetch backend is a capability-negotiating plugin.** One interface, three
capabilities; a backend declares the subset it implements:

| Capability | Meaning |
|---|---|
| `fetch` | Retrieve one granted URL and return Markdown + metadata. |
| `discover` | Enumerate URLs under a granted prefix (site crawl or index query). |
| `search` | Answer a query with URLs + content. Optional; not used by ingestion. |

Configuration selects exactly one ingestion backend (`web.backend`, default
`plain-fetcher` — the option with no third party in it, so selecting a vendor is
always a deliberate act), with a per-backend config block (e.g.
`PRAG_FIRECRAWL_URL`, `PRAG_EXA_API_KEY`). Built-ins: `firecrawl`, `exa`,
`plain-fetcher` (`fetch` only, no dependencies).

**4. Missing capability is a named error, never a silent degradation.** ADR-023's
rule — a user must be able to tell a deliberate limit from a bug — governs here.
`prag watch https://site/**` against a backend without `discover` fails with
`CRAWL_CAPABILITY_UNAVAILABLE`, naming the missing capability and which backends
provide it. Single-URL registration keeps working on any backend that has `fetch`.
There is **no automatic fallback** to another backend: falling back from a
self-hosted instance to a hosted vendor would be an unannounced change of egress
path, which is exactly what this ADR exists to make legible.

**5. Prag enforces grants around the backend, not inside it.** The requested
prefix bounds what Prag asks for; every URL the backend returns is re-evaluated
against the grants table before it is written. A `prag deny https://site/private/**`
must hold even when the backend surfaced that URL via a sitemap, a link, or its
index. Backend output is untrusted input of unknown size, subject to the same
`ingestion.maxFileBytes` ceiling as a local file, and is never interpreted as
instructions.

**6. `validUntil` stays Prag's clock; index-backed content gets a shorter lease.**
Backends do not offer conditional fetches Prag can rely on, so freshness remains
Prag's responsibility (ADR-008): re-fetch on expiry, compare `contentHash`, write
only on change. A backend that sourced its answer from a cache or index of unknown
age must report that, and Prag shortens the resulting `validUntil` accordingly
rather than granting it the full `defaults.webCooldownSeconds`. No new schema
column: the lease is the record.

**7. Crawls are asynchronous jobs.** A `discover` call is long-running and
outlives the request that started it. Prag tracks the outstanding job per project,
can cancel it, and surfaces it through `GET /projects`. `POST /sync` either awaits
it or returns `SYNC_TIMEOUT` (ADR-019, HTTP 504) naming what is still outstanding;
`POST /shutdown` cancels and drains before exit.

## Consequences
- ADR-012 is **superseded**. Its durable decisions — no telemetry ever, web
  ingestion strictly opt-in, nothing sent to remote inference by default — are
  restated above and remain in force. Its Firecrawl-specific clause does not.
- `air-gapped-runtime.md` becomes `local-first-runtime.md`; the README, the
  feature and the enforcement task are reworded from "zero outbound calls" to
  "local content never leaves the machine, and a local cycle works offline".
- `web-and-nonlocal-content.md` describes backends and capabilities instead of
  naming Firecrawl in its title and requirements.
- Tests stub the backend interface rather than one vendor's response shape, so
  each backend gets its own canned fixture and no test performs egress.
- The web default TTL is `defaults.webCooldownSeconds` (86400 = 1 day) everywhere;
  earlier documents variously claimed 1 day and 7 days.
- Unresolved and deliberately deferred: where in-flight crawl-job state lives.
  The current schema has no column for it, and the storage schema has no migration
  strategy beyond drop-and-reindex (`issue:lancedb-schema-migration-strategy.md`).
  In-memory plus project status is the starting point; persisting it is a schema
  decision to be taken with that issue, not smuggled into this one.

## Evaluated Alternatives Ruled Out
- **Keep Firecrawl hard-wired, self-hosted by default (ADR-012 as written):**
  rejected — it forecloses index-backed providers such as Exa whose discovery
  model is fundamentally different, and it protects a guarantee (air-gap) that was
  never true of the web path anyway.
- **Implement a full crawler in the built-in fallback:** rejected — a
  half-implemented crawler (no depth limits, no `robots.txt`, no JS rendering)
  silently under-indexes, which ADR-023 explicitly forbids. Declaring the
  capability absent is honest; pretending to crawl is not.
- **Abstract only `fetch(url) -> markdown`:** rejected — it makes `discover`
  unrepresentable, so a glob grant would either fail or quietly index one page.
- **Let each backend decide freshness:** rejected — backends expose no portable
  conditional-fetch contract, so delegating freshness would either re-embed
  unchanged pages or serve stale content with no way to reason about it.
- **Automatic fallback to a hosted backend when the configured one is down:**
  rejected — silently relocating egress is the failure mode this ADR is written to
  prevent. Fail with a named error and let the user decide.

## Addendum 2026-11-03: crawlberg is the built-in backend

`plain-fetcher` was written as the zero-dependency placeholder this ADR's
"Implement a full crawler in the built-in fallback" clause rules out. It
honoured that clause by declaring only `fetch`, which left two gaps: a bare
origin could not be registered at all, because `discover` had no provider; and
its output was prose, not Markdown, so the heading chunker had no headings to
split on and a page became one undifferentiated chunk.

`@xberg-io/crawlberg` closes both without reopening the clause, because it is
not a half-crawler written here -- it has depth limits, `robots.txt` handling
and a documented SSRF policy. Measured against a loopback origin
(`daemontest:crawlberg-backend.test.ts`):

| | plain-fetcher | crawlberg |
|---|---|---|
| capabilities | `fetch` | `fetch`, `discover` |
| output | prose | Markdown: headings, lists, tables, emphasis |
| page chrome | kept | nav/script/form stripped (`preprocessing_preset: standard`) |
| `robots.txt` | not read | honoured |
| private networks | unrestricted | denied by default |

`plain-fetcher` stays registered. It is the answer for anyone who wants no
native addon in the daemon at all, and keeping it is what makes "exactly one
backend, chosen explicitly" a real choice rather than a single option.

### Where it lives, and why not in core

In `@prag/daemon`. The package resolves to a ~46MB native addon, and
`@prag/core` is on the CLI's import path -- `prag search` must not load a
crawler to print results. Registration is an import side effect of the daemon
entry point and nowhere else.

### Egress is pinned, not inherited

Two findings from reading crawlberg's configuration, both acted on:

- **Private networks are denied by default.** A grant for a public URL is not
  consent to reach the user's LAN. The test suite is the only caller that opts
  out, because its fixtures are served from `127.0.0.1`.
- **`ssrfDenyPrivateExplicit` is pinned.** Left unset, crawlberg treats
  `denyPrivate: true` as inconclusive -- its own structural default is also
  `true`, so it cannot distinguish a caller's intent from a binding's
  boilerplate -- and defers to the `CRAWLBERG_ALLOW_PRIVATE_NETWORK`
  environment variable. That would let a variable prag neither documents nor
  reads widen prag's egress. Pinning it says the decision is prag's.
  `daemontest:crawlberg-backend.test.ts` sets that variable and asserts the
  denial holds.

Also off, each a separate egress or disk decision that has not been taken:
browser rendering, screenshots, asset download, document download.

### Tests get real HTML->Markdown without a network

This ADR requires that no test perform egress, which previously meant canned
fixtures. A loopback HTTP server is better: the real converter runs against
real HTML, so what the suite checks is crawlberg's output rather than a
recorded guess at it, and the socket-level assertion in
`daemontest:local-first-egress.test.ts` still holds because loopback is not
egress. The same pattern is what Firecrawl and Exa should use for the
protocol-shaped parts of their backends, leaving recorded fixtures for the
vendor-specific response bodies only.
