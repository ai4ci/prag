## Context
The indexing system must balance polyglot cross-language code understanding with local hardware constraints on standard development workstations.

## Decision
Standardize on compact polyglot-capable models like `Xenova/bge-small-en-v1.5` or `nomic-embed-text` via local ONNX runtime or Ollama.

## Consequences
Maintains strong cross-language syntax mapping within a fast, low-memory footprint (~130MB on disk) that keeps the system responsive on both CPU and GPU.

## Evaluated Alternatives Ruled Out
### High-Memory Multi-Lingual Processing (BAAI/bge-m3)
- **What it is:** Utilizing a large multi-lingual model capable of parsing across 100+ text and programming language spaces.
- **Why considered:** Exceptionally accurate semantic translation mappings across completely different code structures.
- **Why ruled out:** Too heavy to run as a local background utility on standard development workstations, leading to slow CPU inference speeds and excessive RAM usage.
- **The prag Shift:** Replaced by compact models (~130MB) running efficiently within local workstation perimeters.
