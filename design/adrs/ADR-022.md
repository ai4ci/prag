## Context
ADR-013, ADR-015 and ADR-016 each specify the *prose* of a failure — "Port <n> is in use by a different process", "Configured embedding model <X> does not match..." — and each specifies the remedy the user should follow. None of them specify a shape. There is no error envelope for the HTTP API, no exit-code table for the CLI, and nothing stable for a test or an MCP client to match on.

Matching on message text is the failure mode this invites: it makes every error string a de-facto API, so rewording a sentence for clarity breaks callers. The ADR-019 harness has to assert on failures, so this lands early rather than late.

## Decision
### 1. One envelope, every endpoint
```json
{
  "error": {
    "code": "EMBEDDING_MODEL_MISMATCH",
    "message": "Configured embedding model bge-large does not match the model used to build this index (bge-small-en-v1.5, pinned 2026-10-28).",
    "remedy": "Run `prag reembed` to rebuild, or revert PRAG_EMBEDDING_MODEL to bge-small-en-v1.5.",
    "details": { "configured": "bge-large", "pinned": "bge-small-en-v1.5", "pinnedAt": "2026-10-28" }
  }
}
```
- **`code`** is the contract. `SCREAMING_SNAKE_CASE`, drawn from a closed set exported by `@prag/core`, never localized and never reworded. Tests, the CLI and MCP clients branch on this and only this.
- **`message`** is one human sentence stating what happened.
- **`remedy`** is the action the user can take. The ADRs above already write these; this gives them a home instead of embedding them in prose that callers then parse.
- **`details`** is optional structured context, never required for correct handling.

### 2. HTTP status mapping
| Status | Meaning |
|---|---|
| `400` | malformed request body |
| `401` | missing/invalid bearer token, or rejected `Origin` (ADR-013) |
| `404` | unknown `projectId` |
| `409` | state conflict — embedding model mismatch (ADR-015), rebuild already running |
| `422` | well-formed but failed validation (e.g. `search_local` without `projectId`, ADR-018) |
| `503` | daemon starting, or index unavailable during a rebuild |
| `504` | `POST /sync` drain timeout (ADR-019) |
| `500` | unexpected — always a bug, always logged with a stack trace |

### 3. CLI exit codes
| Code | Meaning |
|---|---|
| `0` | success — **including a search that matched nothing**. Empty results are not an error. |
| `1` | unexpected failure |
| `2` | usage error (bad arguments) |
| `3` | no daemon running (spawn failed, or `PRAG_NO_SPAWN=1`) |
| `4` | daemon identity or `apiVersion` mismatch (ADR-016) |
| `5` | authentication failure |
| `6` | embedding model mismatch — `prag reembed` required (ADR-015) |
| `7` | URI not granted, or unknown project |
| `8` | timeout |

### 4. Rendering
- Default CLI output prints `message`, then `remedy` on the next line. Nothing else.
- `--json` emits the envelope verbatim so scripts get the same structure the API returned.
- MCP tool failures carry `code` and `message` into the MCP error, so an agent gets a machine-readable reason rather than a prose blob.
- `500` is the only status whose `message` may be generic; the detail belongs in the daemon log, not in a response that may reach an agent.

## Evaluated Alternatives Ruled Out
- **Plain-text errors with no envelope:** simplest, and the status quo. Rejected because it forces every caller — including our own test harness — to match on message text, which freezes every error string as API.
- **RFC 7807 `application/problem+json`:** a real standard, and a reasonable choice. Rejected as a poor fit: its `type` URI field is dead weight for a loopback-only API with no public documentation space to point at, and it has no natural slot for `remedy`, which is the field that makes these particular errors actionable.
- **Numeric error codes:** stable and compact, but unreadable in a log and tempting to renumber. String codes cost nothing here.

## Consequences
- Error messages can be reworded freely without breaking callers; only `code` is frozen.
- The harness asserts on `code`, so failure tests do not become string-comparison tests.
- Every new failure path must pick a `code` and a `remedy`, which is a small deliberate tax on adding failure modes.
- `cli-and-mcp-interface.md` carries the envelope, the status mapping and the exit-code table.
