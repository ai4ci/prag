## Context
Nothing in the accepted requirements describes how `prag` is to be tested. Auditing the specification against the needs of an automated harness found that the raw material is mostly present — `PRAG_DATA_DIR`, `PRAG_CONFIG_DIR`, `PRAG_RUN_DIR`, `PRAG_LOG_DIR`, `PRAG_PORT` and `PRAG_DEBOUNCE_MS` are all overridable, `POST /sync` can force a flush, `POST /shutdown` can terminate cleanly — but that four separate gaps make a correct harness impossible to write as specified, and one of them is actively dangerous.

1. **Isolation is per-directory and fails open.** A harness must set four independent variables correctly. Miss one and that category silently falls back to the developer's real XDG path. `PRAG_RUN_DIR` missed means the test writes `daemon.pid`/`daemon.port`/`daemon.token` over the developer's live daemon's files and may shut it down. `PRAG_DATA_DIR` missed is worse: `prag reembed` drops every content table (ADR-015) and `prag prune --gc-chunks` deletes and compacts (ADR-017), so a single missing variable in a test turns a routine run into the destruction of the developer's real index. There is no way for a harness to assert "I am isolated" before doing anything destructive.
2. **Embedding cannot be faked.** ADR-006 pins real ONNX weights (~130MB, downloaded on first use). Every test that indexes anything therefore needs those weights, takes model-load time, and asserts against ranking that shifts between model revisions. It also makes `local-first-enforcement.md`'s own requirement — assert zero outbound connections during an index+search cycle — unsatisfiable on a cold machine, because the first run downloads the model.
3. **Port allocation has no test-safe mode.** ADR-016 deliberately forbids fallback port scanning, which is right for production and leaves parallel test workers colliding on `7724` with a hard, by-design failure.
4. **Lifecycle cannot be controlled.** Lazy auto-spawn creates a `detached: true, stdio: 'ignore'` process. A test that fails before teardown leaves an orphan daemon holding a port and a temp directory the harness then deletes underneath it. There is no documented way to say "do not spawn, I manage the daemon."

## Decision
Four additions, all of which also have non-test value.

1. **`PRAG_ROOT` — one variable isolates everything.** When set, all four base directories derive from it: `<root>/data`, `<root>/config`, `<root>/state`, `<root>/state/logs`. An individually-set `PRAG_DATA_DIR`/`PRAG_CONFIG_DIR`/`PRAG_RUN_DIR`/`PRAG_LOG_DIR` still wins over the derived path; unset ones no longer fall back to XDG. A harness sets one variable to a temp directory and is fully isolated, and teardown is one recursive delete of one path.
2. **`/health` reports its resolved paths** (`root`, `dataDir`, `configDir`, `runDir`). A harness asserts the daemon it is talking to is rooted inside its own temp directory *before* running anything destructive, turning a silent catastrophe into a failed assertion. This is also the first thing to ask a misbehaving daemon in production.
3. **`PRAG_PORT=0` binds an ephemeral port.** The kernel-assigned port is written to `daemon.port` as usual, and clients read it from there rather than from configuration. This is the only supported way to run daemons in parallel; it does not reintroduce the port scanning ADR-016 rejected, because the port is still discovered from a known file, never guessed.
4. **`PRAG_NO_SPAWN=1` disables lazy auto-spawn.** The CLI fails immediately with "no daemon running and PRAG_NO_SPAWN is set" instead of forking a detached process. The harness owns daemon lifetime, so a crashed test leaves nothing behind.
5. **Injectable embedding provider.** `PRAG_EMBEDDING_MODEL` accepts a `fake:<dim>` form (e.g. `fake:384`) selecting a deterministic, dependency-free embedder built into `@prag/core`: the vector is derived from a hash of the input text. It is not semantically meaningful — it is reproducible, instant, and offline. Tests that assert *plumbing* (dedup, branch pointers, project scoping, chunk counts, vectorised-unit counts) use it. Tests that assert *retrieval quality* use the real model and are a separate, explicitly-run tier. The fake model is pinned in the ADR-015 sidecar like any other, so switching between tiers is caught rather than silently mixed.
6. **`POST /sync` is a drain barrier.** It returns only once the ingestion queue is empty, every pending debounce and cooldown lease has been forced, and all writes are committed. Without this guarantee a harness has no way to know when indexing has finished and every test is a race. This tightens an existing endpoint rather than adding one.

## Evaluated Alternatives Ruled Out
- **Leave isolation to the harness setting four variables correctly:** possible, but the failure mode is silent and destroys real user data, and every consumer of the project would have to reimplement it correctly.
- **A dedicated `PRAG_TEST_MODE` flag:** rejected — a code path that only exists under test is a code path that is never really tested. `PRAG_ROOT`, ephemeral ports and no-spawn are ordinary configuration that happen to be what a harness needs; the production paths stay the paths under test.
- **Injectable clock for `validUntil` leases (ADR-008):** rejected as unnecessary. `defaults.localCooldownSeconds` and `PRAG_DEBOUNCE_MS` are already configurable, so lease behaviour is tested with sub-second leases and a real wait, and lease *suppression* is tested with a long lease plus `POST /sync` to force the flush. A handful of short real sleeps is cheaper than threading a clock through the daemon.
- **Committing pre-built git repositories as fixtures:** rejected — a nested `.git` directory does not survive being committed to this repository. Git fixtures are assembled by a builder script at setup time, with pinned author/committer dates so commit hashes are stable.

## Consequences
- A harness is: set `PRAG_ROOT` to a temp dir, set `PRAG_PORT=0` and `PRAG_NO_SPAWN=1`, start the daemon, assert `/health` is rooted where expected, run, `POST /shutdown`, delete the root.
- Isolation failure becomes a failed assertion instead of data loss.
- `env-and-storage-paths.md` gains `PRAG_ROOT`, `PRAG_NO_SPAWN` and the `PRAG_PORT=0` semantics; `cli-and-mcp-interface.md` gains the `/health` path fields and the `/sync` drain guarantee.
- The fake embedder is shipped in production code, not test-only code. It is reachable by a user who configures it, which is acceptable: it is explicit, pinned in the sidecar, and useful for smoke-testing an install without a model download.
