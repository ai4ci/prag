## Context
Formatters and linters (Prettier, Black, rustfmt, ruff) frequently reformat indentation, trailing spaces, and line breaks across entire repositories. If chunk hashes (`chunkHash`) are computed over raw, unnormalized source text, running a code formatter invalidates every chunk in a file, forcing expensive re-embedding of identical logic across thousands of chunks.

Conversely, comments and docstrings contain critical semantic explanations (*why* code exists, parameter meanings, domain concepts) that are vital for natural language retrieval matching.

## Decision
Retain comments and docstrings in both chunk text and embeddings, but apply structural whitespace normalization before computing `chunkHash`:
1. **Preserve Comments:** Comments and docstrings remain intact inside the chunk text and contribute to the embedding vector.
2. **Normalize Whitespace for Hashing:**
   - Collapse non-semantic whitespace sequences, normalize line endings (`\r\n` -> `\n`), strip trailing whitespace per line, and trim leading/trailing empty lines.
   - For indentation-sensitive languages (e.g. Python), preserve syntactic indentation levels derived from the Tree-sitter parse tree while standardizing indentation tokens (e.g. 4 spaces).
3. **Deduplication Win:** When a file undergoes formatting or re-indentation without semantic or comment changes:
   - The file's content hash changes in `file_mapping`, but every extracted chunk yields the identical normalized `chunkHash`.
   - Existing rows in `chunks_pool` are matched with zero ONNX embedding calculation.
   - Only `chunk_mapping` and `branch_mapping` pointers update.

## Evaluated Alternatives Ruled Out
- **Raw Literal Text Hashing (No Normalization):**
  - *Why considered:* Simplest implementation (`sha1(rawText)`).
  - *Why ruled out:* Every automated lint/format run causes massive vector recalculation and database churn for purely cosmetic changes.
- **Stripping Comments and Docstrings:**
  - *Why considered:* Ensures hashes reflect only functional logic.
  - *Why ruled out:* Destroys the highest-value semantic signals for natural language search queries; developers often search by phrasing described only in comments or docstrings.

## Consequences
- Code reformatting, lint passes, and cosmetic whitespace adjustments produce zero vector re-embedding overhead.
- High-quality natural language search performance is preserved because comments remain embedded.
- Tree-sitter handles language-specific nuances (like Python indentation) reliably.
